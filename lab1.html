¿Qué vas a aprender?

Este lab demuestra cómo usar las features de Bob Premium para documentar una aplicación Java existente de forma profesional y en minutos. En lugar de un único prompt genérico, construirás un asistente especializado desde cero usando Skills, Custom Modes, Slash Commands y el flujo de modos Ask → Plan → Agent.

El proyecto a documentar es JOSSO Gateway: un servidor de Single Sign-On (Java 8, Maven multi-módulo, Struts + Axis + JSP) pensado para WebLogic, el mismo que migrarás a Liberty en el Lab 2. Documentarlo primero te da el mapa del proyecto antes de modernizarlo.

Mismo ZIP que el Lab 2: descarga lab2-migracion.zip, descomprímelo y luego descomprime JOSSO-weblogic-bob-4.zip. La carpeta JOSSO-weblogic-bob-4 es el proyecto que abrirás en Bob.

Paso 0 · Configurar el asistente (5 min)

Abre la carpeta del proyecto JOSSO-weblogic-bob-4 en Bob. Ejecuta cada uno de los siguientes prompts en modo Agent para crear los archivos de configuración de Bob dentro del proyecto.

A · Custom Mode — java-documenter

Un Custom Mode define el rol, los permisos y las instrucciones base de Bob para una tarea específica. Este modo solo puede leer, escribir documentación y usar skills: no tiene acceso a la terminal, así que Bob no puede ejecutar comandos ni compilar por accidente.

Prompt:

Crea el archivo .bob/custom_modes.yaml con el siguiente contenido exacto:

customModes:
  - slug: java-documenter
    name: 📄 Java Documenter
    description: Modo especializado para analizar y documentar proyectos Java existentes.
    roleDefinition: >-
      Eres un arquitecto de software senior especializado en documentar proyectos Java empresariales.
      Tu único objetivo es analizar el código existente y producir documentación técnica clara,
      completa y en español. Nunca modificas archivos de código fuente.
    whenToUse: Úsalo cuando necesites documentar un proyecto Java existente.
    customInstructions: >-
      Documenta siempre en español. Incluye tabla de puntos de entrada web (URL, servlet o acción, descripción).
      Cita versiones exactas desde los pom.xml. Organiza la documentación por módulos: shared, gateway, agent.
    groups:
      - read
      - edit
      - skill
El grupo read permite leer archivos. El grupo edit permite escribir archivos como DOCUMENTACION.md (las instrucciones del modo le piden no tocar el código fuente). El grupo skill permite activar los skills definidos en .bob/skills/. No se incluye command para que Bob no pueda ejecutar comandos de terminal.

B · Skill — java-doc-expert

Un Skill es un conjunto de instrucciones especializadas almacenadas en .bob/skills/<nombre>/SKILL.md. Bob lo activa automáticamente cuando detecta que es relevante, o se invoca manualmente con /java-doc-expert. A diferencia de un prompt en el chat, el skill persiste y se puede reutilizar en cualquier proyecto Java.

Prompt:

Crea el archivo .bob/skills/java-doc-expert/SKILL.md con el siguiente contenido exacto:

---
name: java-doc-expert
description: Úsalo cuando el usuario quiera documentar un proyecto Java existente. Genera documentación técnica completa en español.
---

# Java Documentation Expert

Cuando se active este skill, analiza el proyecto Java abierto y genera documentación técnica completa.

## Qué debes documentar

1. **Descripción general** — propósito de la aplicación y problema que resuelve
2. **Stack tecnológico** — versiones exactas desde los pom.xml (Java, Spring, Struts, Axis/CXF, dependencias clave)
3. **Arquitectura** — estructura multi-módulo del repositorio (shared, gateway, agent) y responsabilidad de cada módulo
4. **Componentes clave** — autenticador, gestor de sesiones, identity store, auditoría y cómo se conectan entre sí
5. **Puntos de entrada web** — tabla con URL, servlet o acción (web.xml, struts-*.xml), JSPs de administración y servicios SOAP
6. **Configuración** — archivos como josso-gateway-config.xml, josso-users.xml, josso-credentials.xml y web.xml
7. **Cómo construir y ejecutar** — perfiles de Maven, Makefile y archivos de docker/ para correr la aplicación
8. **Dependencias de plataforma** — código o configuración que asume WebLogic (relevante para migrar a Liberty)
9. **Observaciones** — posibles mejoras, deuda técnica o puntos de atención

## Formato de salida

- Escribe en español
- Usa headers Markdown (##, ###)
- Usa tablas para puntos de entrada web y componentes
- Sé preciso: cita nombres de clases, métodos y archivos reales del proyecto

C · Slash Command — /doc-java

Un Slash Command es un archivo .md dentro de .bob/commands/. El nombre del archivo se convierte en el comando. Al escribir /doc-java en el chat, Bob ejecuta las instrucciones del archivo de forma inmediata. Es la forma de estandarizar workflows del equipo sin depender de que cada persona recuerde el prompt correcto.

Prompt:

Crea el archivo .bob/commands/doc-java.md con el siguiente contenido exacto:

Activa el skill java-doc-expert y genera la documentación técnica completa
del proyecto Java actualmente abierto.
Haz dos cosas con el resultado:
1. Guarda la documentación en un archivo llamado DOCUMENTACION.md en la raíz del proyecto.
2. Genera también un HTML artifact con el mismo contenido: una página estática bien
   estructurada con secciones, tablas y formato legible, lista para compartir.

D · Mode-specific rules — java-documenter

Las mode-specific rules se almacenan en .bob/rules-{slug}/ y se aplican únicamente cuando ese modo está activo. Permiten imponer estándares de equipo sin tener que repetirlos en cada prompt.

Prompt:

Crea el archivo .bob/rules-java-documenter/standards.md con el siguiente contenido exacto:

# Estándares de documentación Java

- Toda la documentación debe estar escrita en **español**
- Los puntos de entrada web siempre deben presentarse en tabla con columnas: URL | Servlet/Acción | Descripción
- Las versiones del stack deben extraerse del pom.xml, nunca suponer versiones
- Si no encuentras información suficiente para una sección, indícalo explícitamente
- No generes código nuevo ni modifiques archivos del proyecto
Al terminar el Paso 0 tendrás esta estructura dentro del proyecto JOSSO-weblogic-bob-4:

.bob/custom_modes.yaml — define el modo java-documenter
.bob/skills/java-doc-expert/SKILL.md — instrucciones de documentación
.bob/commands/doc-java.md — slash command /doc-java
.bob/rules-java-documenter/standards.md — reglas del modo

Paso 1 · Explorar el proyecto Ask mode · 2 min

Con el proyecto JOSSO Gateway abierto en Bob, cambia al modo Ask haciendo clic en el selector de modo a la izquierda del campo de chat y seleccionando Ask, o escribe /ask en el chat.

Ask mode solo puede leer archivos — nunca modificarlos. Es el modo correcto para explorar un proyecto desconocido sin riesgo de cambios accidentales.

Prompt:

Explícame qué hace esta aplicación, qué problema resuelve y cómo está estructurada.
Identifica los módulos principales (shared, gateway, agent), los componentes clave del SSO y los puntos de entrada web disponibles.

Observa cómo Bob navega por los archivos (pom.xml, web.xml, módulos de shared y gateway, Makefile) sin proponer ningún cambio. Ese es el comportamiento correcto de Ask mode.

Paso 2 · Planear la documentación Plan mode · 3 min

Cambia al modo Plan desde el selector de modo o escribe /plan en el chat. En Plan mode Bob propone estructuras y organiza el trabajo — tampoco escribe archivos todavía.

Prompt:

Basándote en lo que analizaste del proyecto JOSSO Gateway, diseña la estructura
de la documentación técnica que generaremos.
Propón las secciones que debe tener el archivo DOCUMENTACION.md, en qué orden y por qué
cada una es relevante para este proyecto específico.

Bob propondrá un índice justificado. Puedes ajustar lo que no te convenza antes de generar nada. Este paso separa el "qué documentar" del "cómo escribirlo" — un hábito clave al trabajar con agentes en proyectos reales.

Paso 3 · Generar la documentación java-documenter mode · 5 min

Cambia al modo 📄 Java Documenter que creaste en el Paso 0. Aparecerá en el selector de modo junto a Ask, Plan y Agent.

Verás que Bob adopta el rol de arquitecto documentador: lee el proyecto, escribe la documentación y usa skills, pero no ejecuta comandos de terminal. Ahora escribe en el chat: 

/doc-java

Bob activará el skill java-doc-expert, aplicará los estándares del modo y generará el archivo DOCUMENTACION.md en la raíz del proyecto con la documentación técnica completa del sistema JOSSO Gateway.

Si Bob solicita confirmación para activar el skill, haz clic en Aprobar. Para evitar esta confirmación en el futuro, activa Settings → Auto-Approve → Skills.

Una vez generado el archivo, ábrelo y verifica que incluya las secciones definidas en el skill: stack tecnológico, arquitectura multi-módulo (shared, gateway, agent), componentes clave, tabla de puntos de entrada web (*.do, /services/*, páginas de admin/), dependencias de WebLogic y pasos para construir y ejecutar la aplicación.

Bonus · /init y AGENTS.md (opcional · ~2 min)

Solo si te sobra tiempo. /init es un comando integrado de Bob que escanea el proyecto y genera un AGENTS.md: un resumen de estructura, convenciones y objetivos que Bob lee al inicio de cada conversación. Sin él, Bob es stateless y tiene que redescubrir el proyecto cada vez.

Cómo usarlo: con la carpeta raíz JOSSO-weblogic-bob-4 abierta, en modo Agent escribe:

/init

Si el auto-approve está desactivado, Bob pide permiso para leer archivos y escribir. Al terminar verás un AGENTS.md en la raíz y, dentro de .bob/, un archivo de reglas por cada modo integrado.

HerramientaPara qué sirveCuándo
/init → AGENTS.mdQue Bob conozca el proyectoUna vez, y de nuevo tras cambios grandes
SkillInstrucciones de cómo hacer un tipo de tarea, reutilizables entre proyectosCuando Bob detecta que aplica, o a mano
Slash commandAtajo que dispara un flujo del equipoCuando lo escribes
Abre siempre la carpeta raíz del proyecto: si abres una subcarpeta, Bob ve solo un fragmento y puede generar un AGENTS.md escaso. Revisa el resultado y edítalo si hace falta. Vuelve a ejecutar /init si cambias la estructura del proyecto.
