Descripción de la app

JOSSO Gateway es un servidor de Single Sign-On que permite a los usuarios autenticarse una sola vez y acceder a múltiples aplicaciones sin volver a ingresar sus credenciales. Incluye un panel de administración para monitorear en tiempo real el estado del servidor, la salud de los componentes y las librerías cargadas. Está diseñado para correr en WebLogic con Java 8 y se gestiona desde línea de comandos con Podman y Make.

Objetivo del laboratorio

Migrar JOSSO Gateway de WebLogic 12.2.1.4 a WAS Liberty sin cambiar la lógica de negocio: adaptar configuración del servidor, contenedor y puntos donde el código asume WebLogic.

El workflow de Java Modernization de Bob guía paso a paso el proceso de mover una aplicación Java de un servidor legacy a Liberty.

Qué modificó el workflow

Antes de verificar que Liberty levanta, conviene entender qué cambió Bob. Estos son los archivos clave que el workflow modifica:

ArchivoQué configuró Bob
gateway/src/main/liberty/config/server.xml Features de Liberty, puertos HTTP/HTTPS, configuración de la aplicación WAR y credenciales del Admin Center
Containerfile Imagen base Liberty, rutas de copia del WAR y librerías al contenedor
Makefile Variables de puertos (LIBERTY_HTTP, LIBERTY_HTTPS), target liberty-setup con el comando podman run
gateway/web/target/*.war WAR compilado listo para desplegar: josso-gateway-web-1.8.12-SNAPSHOT.war
Si el workflow terminó sin errores pero Liberty no arranca, el problema suele estar en server.xml (features incorrectas) o en el Makefile (puertos ocupados). Ve a la sección Prompts de recuperación más abajo.

Prompts de recuperación ante errores

Estos son los tres errores más frecuentes después del workflow. Copia el prompt correspondiente directamente en Bob — no necesitas diagnosticar nada tú mismo.

Liberty no levanta · sin logs o contenedor que no arranca

El servidor Liberty no está arrancando. Revisa si hay algún contenedor de Podman corriendo
o detenido con el nombre josso. Muéstrame los logs del contenedor si existe.
Si no existe, revisa el Makefile y dime exactamente qué comando podman run se ejecutaría
con las variables actuales. Identifica qué puede estar fallando antes de intentar levantarlo de nuevo.

Error de autenticación · credenciales no funcionan

Las credenciales del Admin Center de Liberty no están funcionando.
Lee el server.xml y dime exactamente qué usuario y contraseña están configurados
en el elemento quickStartSecurity. Si usan variables, búscalas en bootstrap.properties
o en el Makefile. Dame las credenciales exactas que debo usar.

Endpoints no responden · curl falla con conexión rechazada

Los endpoints de JOSSO no responden. Verifica:
1. Si el contenedor de Podman está corriendo: podman ps
2. En qué puerto quedó mapeado: podman port josso (o el nombre del contenedor)
3. Si el WAR está desplegado: busca en los logs "CWWKZ0001I" que indica app iniciada
4. El context-root configurado en server.xml
Dame un diagnóstico de qué está pasando y el comando curl correcto para probar cada endpoint.
Si ninguno de estos prompts resuelve el problema, reinicia desde cero con el prompt de liberar puertos de la sección anterior y vuelve a ejecutar make liberty-setup.
